# Latency sweep — 2026-08-08

Generated by `node scripts/latency-sweep.js` against a local backend, one golden
case per tool. **These are the SMALL fixture inputs — real user inputs are larger**,
so treat every number as a floor.

Safari abandons a fetch at roughly 60s and reports "Load failed"; the tool looks
broken while the server is still working. 45s is the warn line, because a slightly
bigger input than the fixture crosses from one band to the other.

**Nothing on the worklist is over 60s any more.** The 18 routes the 2026-08-07
sweep flagged now run 31–57s; 8 of them sit in the 45–60s warn band. Two things
found along the way are NOT fixed and are written up at the bottom: `pre-mortem`
at 100s, and four golden fixtures that cannot reach their own endpoint.

## What actually made the difference

**The grounding pre-pass was the single biggest item, and it was not a split.**
Six routes await a web-search pre-pass before generating. It was bounded at 25s
on 2026-08-07 to keep it inside the browser limit. Timing the search itself shows
that bound could never be met: it takes ~50s regardless of `max_uses` (3 → 52s,
2 → 52s, 1 → 49s). So it timed out every single time — every cold request paid
25s and got an EMPTY verified-law block back. It also truncated at
`max_tokens` 2500, so even a pre-pass that beat the clock would have thrown.

`groundedFacts` is now stale-while-revalidate: the request never waits, a cached
block is returned immediately, and a missing or expired one kicks the search off
in the background so the *next* request for that jurisdiction is grounded.
Budget raised to 6000 — 9 verified rules in ~72s. Strictly better on both axes.
Cost: the first user per jurisdiction after a deploy gets the unverified hedge,
which is what they got before anyway, just without the 25s attached.

**Where a schema has no key-wise seam, partition the structure itself.** Four
routes had one array or object that *was* the response. Splitting them needs a
partition rule the two calls cannot both satisfy:

- heckler-prep — by question type (Data/Logic, Practical, Political \| Emotional, Gotcha, Values)
- the-crux — by which half of the lecture transcript the questions are drawn from
- plaintalk — by document half, cut at the paragraph boundary nearest the midpoint
- complaint-escalation-writer — by rung of the escalation ladder

An index split ("questions 1-5 \| 6-10") does not work: nothing stops both calls
writing the same question. Merging then has to restore whatever order the tool
promised — heckler-prep re-sorts by escalating difficulty and renumbers,
plaintalk renumbers section ids across the join.

**Splitting a prompt drops whatever length discipline lived in the shared text.**
Both plaintalk analysis halves truncated at first because "keep short fields to
one concise sentence" stayed behind in the half that no longer existed. Check for
this after every split — the symptom is a 500, not a long answer.

**Two enum bugs surfaced because the merge code started depending on them.**
heckler-prep sorts on `difficulty` and difficult-talk-coach's UI does
`levelConfig[msg.level]`; neither was pinned to English, so `withLanguage` was
free to translate them and every non-English user got the fallback. Both are now
pinned. Fields that are only *rendered* (heckler-prep's `type`) were left
translated.

**Diff the schema keys after every split.** `the-crux` has three endpoints whose
prompts all begin `const userPrompt = \`LECTURE CONTENT:`; a splice anchored on
the first match and gutted two unrelated prompts. The key diff caught it (33 keys
missing) before it went anywhere. Anchor edits relative to the target route's own
`router.post` line.

## Still open

**`pre-mortem` — 100s.** It was in the old "not measured" bucket (connection
error mid-run), so it never made the worklist. It is measurable now and it is the
slowest route in the catalog. Not touched here.

**Four golden fixtures cannot reach their own endpoint, and `check:golden` is
failing silently past them.** The `endpoint` field carries a human annotation:

```
"endpoint": "/api/pep (generate)"
```

which POSTs to a URL containing " (generate)" and 404s. This affects the sweep
*and* `check:golden` — `npm run check:golden pep` reports FAIL on all three cases
for this reason alone. The annotation belongs in the case `name`. Four tools have
had no working golden: `fake-review-detective`, `one-percenter`, `pep`,
`spiral-stopper`. Their recorded `output` has never been compared against
anything, so fixing the URL may well surface real drift underneath.

**The rest of the catalog has not been re-measured** since 2026-08-07. The 45-60s
band from that run (giftology 59, upsell-shield 57, bill-rescue 57,
ticket-tackler 56, leverage-logic 55, …) is unchanged except where the grounding
fix touched it — bill-rescue, renters-deposit-saver and ticket-tackler each lose
up to 25s on their cold path.

## Caveats

- Single measurements vary by roughly 20% run to run; re-measure before concluding a fix worked.
- Concurrency 3 inflates by roughly 8% against serial. The after-column above was measured at concurrency 3, so it is, if anything, pessimistic.
- **Neither "SSE stream" in the previous version of this file is a stream.**
  `contract-decoder/stream` and `sleep-architect/stream` both end in `res.json` —
  the name is vestigial. Their durations mean exactly what every other row means.
- Routes using `groundedFacts` are worth measuring twice: the first request per
  jurisdiction after a restart now returns *without* verified law rather than
  waiting for it, so cold and warm differ in content, not in time.
