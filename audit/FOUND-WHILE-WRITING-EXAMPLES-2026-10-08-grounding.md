# Grounding the three held tools (2026-10-08)

- **DateNight — fixed, indexed.** Venue names were already web-verified (lib/venues.js); the planner's added details were not. New `checkVenueClaims` (SMART supplied-facts check) compares every place-specific detail against the search block and cuts or softens what isn't there. Correction to the earlier log: "Restaurant Francois at The Driskill" is real (search-confirmed, opened 2026), and "Thu-Sat" / "well-lit" come from the search notes themselves. Seen in testing: a repair wrote "the confirmed notes describe…" into a tip — repair note now forbids mentioning sources; one repair left "live jazz every night" beside "Thu-Sat".
- **NameAudit — fixed, indexed.** `existingUses` runs a web search for the name (parallel with the analysis, ≤45s cold wait, 14-day cache), keeps only matches whose page was actually retrieved, and `applyExistingUses` folds them into verdict / bottom line / problems. Code caps the verdict: a live same-field match is never STRONG/GOOD FIT. Loomly: GOOD FIT → HAS PROBLEMS, citing loomly.com. Two runs gave different EUIPO filing/registration dates, so the example shows only the loomly.com finding.
- **PlotHoleFinder — still HELD.** Added `plotSynopsis` (web-searched plot summary, 30-day cache) + `checkStoryClaims` (flags story claims that CONTRADICT the summary, SMART). Catches gross errors (e.g. who reads Gordon's speech) but summaries carry little timing, and this tool's errors are mostly timing/logic: a run called the autopilot fix a "YES — REAL HOLE" ("no plausible window") and the check only removed the timing, leaving the verdict. Needs a different approach (e.g. verdicts of YES require the contradiction's two premises to be found in the summary).
