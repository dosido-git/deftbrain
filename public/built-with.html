How DeftBrain is built

Hello, Product Hunt. Thanks for stopping by. Most of DeftBrain is written for someone in the middle of something — a confusing bill, a hard conversation, a lease they're about to sign. This page is for the rest of you: the people who want to see what's under the hood. Here it is, plainly.

The short version

DeftBrain is a React single-page app with an Express/Node backend, hosted on Railway. Each of its 120+ guided experiences sends what the visitor tells it to Anthropic's Claude models through its own backend route, and the answer streams back to the page in parts, each one shown as soon as it's ready. The site runs in 13 languages, and every page is also prebuilt as static HTML, so search engines can read it without running the app.

Frontend

  • One React page per experience, built with Create React App.
  • Shared components for copy, print and share, and an error boundary around every experience, so one broken answer never blanks the page.
  • Light and dark themes throughout.
  • Tailwind, written with direction-neutral spacing, so the whole site mirrors correctly in Arabic.

Backend

  • Express on Node, one route file per experience. A new file is picked up and mounted automatically.
  • Model choice lives in one place: mostly Claude Sonnet, with faster or deeper models for particular steps, each overridable by environment variable.
  • Calls retry on temporary errors and fail fast, with a clear error, when an answer would be cut off.

How an answer is made

  • Split and streamed. A long answer is divided into smaller requests that run at the same time, each writing only its own section. The first part usually appears within seconds; the rest arrive as they finish.
  • Decided once. Where parts must agree — a verdict, a list of findings — a short first step decides it, and every later part follows that decision, so sections can't contradict each other.
  • Checked after. Once the answer is on screen, separate checks look at its numbers, facts and internal consistency, and any correction is shown.
  • Grounded where it matters. Some experiences look things up on the web first — rules, prices, programs — so their claims rest on real sources, which are listed.

Thirteen languages, four layers

  • The answer is written in the visitor's language.
  • The reasoning fits their country — its rules, prices and customs.
  • Currency, numbers and dates are formatted the local way.
  • Every interface string is translated, and right-to-left languages are fully mirrored.

Readable without JavaScript

  • Every experience and guide is prebuilt as a static page: what it's for, what you give it, what you get, frequently asked questions (with FAQ markup), and a real example run.
  • Sitemaps, plus llms.txt files for AI assistants.

Privacy by design

  • No accounts and no sign-up.
  • What you type goes to our server, to Anthropic to prepare your result, and back to you. We don't store your input or your results.
  • Usage is counted by our own small event log, with no user IDs. The details are in the privacy policy.

How it stays reliable

  • Every push runs a set of gates first: syntax and lint checks with zero warnings allowed, audits across the whole catalog, and checks that every language is complete.
  • Each experience has saved example answers. A change replays them for free; a change to what the experience asks the model triggers one real, paid run before it ships.
  • The example on each page is a real run, shown as it came back.

Who builds it
